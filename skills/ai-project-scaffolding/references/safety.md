# 安全与写入边界

## 写入前

- 目标欠明确先问项目目录名; 目标或计划改变须重新展示并确认. --plan 与 --apply 分开调用, 中间等待用户回复.
- 写入前取得用户授权; 只规划的请求不能执行创建.
- 可能产生覆盖的操作前, 先询问是否已备份, 以及是否可回滚.
- 删除、移动或重命名人创建的内容须有明确授权.

## 创建行为

- 仅建缺失项, 不覆盖非空文件.
- 零字节 .gitignore / .gitattributes 可补默认值.
- 无事务回滚: 创建前已发现的根项冲突不写入; 检查后的 IO 错误可留下部分根项; 先检查问题再重试, 已存在的同类型项会跳过.
- 不创建 .git; git init 由用户决定.

## 网络与凭据

- 工具离线运行, 不下载模板.
- 不读写凭据、token 或 .env 内容.
- 脚本只用 Python 标准库, 不执行外部命令.

## 完成证据

- B/C: 报告创建错误和根闸结果; 根闸 exit 0 表示结构通过, exit 1 表示失败, exit 2 表示用法错误.
- A: 没有根闸退出码, 报告手工清单并声明“未跑闸”; 不得把手工判断冒充根闸通过.
- 只规划: 交付计划与判档依据, 不声称项目已创建; 根闸不证明文档正文或发布质量合格.

## 协议文案

内部中文问题和创建标记由 scripts/standard.py 的 core_message 转成英文协议. 修改这些字符串时须同步英文模板, 否则诊断会回退到原始文本.
